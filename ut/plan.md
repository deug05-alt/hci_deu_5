# 사용성 평가 계획

- 평가할 것: `design/prototype.html` (차근차근 모바일 웹 프로토타입)
- 같은 계획을 클로드 가상 UT(`/ut-claude`)와 사람 UT(참가자 3명)에 모두 써요.
- 팀이 가장 걱정하는 것: 재테크를 시작하기 어려워하는 사람이 자기에게 맞는 금융 상품을 어떻게 찾아야 하는지 알게 되는가. 용어가 어렵고 알아볼 게 많아서 중간에 그만두지 않을까.

## 평가 목표
1. 진단을 마친 사람이 로드맵을 보고 **'지금 할 일'과 알아볼 상품 종류**를 말할 수 있는지 확인한다.
2. 적금·ISA 단계 상세 화면(3.3, 3.4)에서 **읽을 양 때문에 지치거나 멈추는 곳**이 있는지, 그 단계를 끝까지 마치는지 확인한다.
3. 상품 종류 안내를 본 뒤 **'나에게 맞는 상품 예시'가 필요하다고 느끼는지** 확인한다.

어려운 용어(원금, 파킹통장, 적금, ISA 등)를 스스로 찾아보고 이해하는지는 목표 1, 2를 보면서 함께 관찰해요.

이 평가가 끝나면 정할 것:
- 로드맵(3.0)에서 '지금 할 일'이 잘 보이도록 바꿀 곳
- 단계 상세 화면(3.3, 3.4)의 설명 양 (줄일지, 나눌지)
- 로드맵을 마친 뒤 나에게 맞는 추천 상품 예시를 보여 줄지

## 과제

과제 문장은 참가자에게 그대로 읽어 줘요. 화면·메뉴·버튼 이름은 일부러 넣지 않았어요.
과제 2, 3에서는 앞 단계를 '이미 했어요'로 넘겨도 성공으로 봐요.

### 과제 1: 첫걸음 찾기 (핵심 플로우, 플로우 1)
- 과제 문장: "취업한 지 몇 달 됐어요. 월급이 들어오는데 통장에 그냥 쌓여만 있어요. 이 서비스로 나는 무엇부터 하면 되는지 알아보고, 오늘 바로 할 수 있는 첫 번째 일을 해 보세요."
- 시작 화면: 시작 화면 (1.0)
- 성공 기준: 진단 3문항을 마치고 맞춤 로드맵(3.0)에서 0단계를 끝낸 뒤, 1단계 상세(3.2)에서 '다 했어요'를 눌러 로드맵으로 돌아온다. 과제가 끝났을 때 "지금 할 일은 ○○이에요"라고 자기 말로 말할 수 있다.
- 예상 단계 수: 약 10 (1.0 → 2.1 → 2.2 → 2.3 → 2.4 → 3.0 0단계 항목 → 3.0 1단계 열림 → 3.2 → 3.0)
- 관련 목표: 1 (용어 관찰: 2.4 기초 용어 미리 보기, 밑줄 용어 3.1)

### 과제 2: 수입이 들쭉날쭉할 때 적금 정하기 (시나리오 B, 플로우 3)
- 과제 문장: "프리랜서로 일해서 달마다 버는 돈이 달라요. 적금을 들어 보고 싶은데, 나에게 맞는 적금은 어떤 것이고 매달 얼마씩 넣으면 될지 정해 보세요."
- 시작 화면: 시작 화면 (1.0). 진행하는 사람이 페이지를 새로 고쳐 기록을 지운 뒤 시작해요.
- 성공 기준: 수입 질문(2.3)에서 '달마다 차이가 있어요'를 고르고, 2단계 상세(3.3)에서 유연한 상품 안내를 본 뒤 납입 금액을 정해 체크하고 '다 했어요'를 눌러, 로드맵에서 2단계가 완료로 보인다.
- 예상 단계 수: 약 11 (1.0 → 2.1 → 2.2 → 2.3 → 2.4 → 3.0 0단계 → 3.0 1단계 → 3.0 2단계 카드 → 3.3 → 3.0)
- 관련 목표: 2, 3

### 과제 3: 돈이 줄어드는 게 무서울 때 세금 혜택 알아보기 (시나리오 C, 플로우 4)
- 과제 문장: "모은 돈이 조금이라도 줄어드는 건 정말 싫어요. 그래도 세금을 아낄 수 있는 방법이 있다면 알아보고 싶어요. 그런 방법을 내가 쓸 수 있는지 확인해 보세요."
- 시작 화면: 시작 화면 (1.0). 진행하는 사람이 페이지를 새로 고쳐 기록을 지운 뒤 시작해요.
- 성공 기준: 손실 불안 질문(2.2)에서 '조금만 줄어도 잠이 안 와요'를 고르고(로드맵 3.0b), 3단계 상세(3.4)에서 조건 두 개에 답한 뒤 '다 했어요'를 눌러 로드맵(3.0b)으로 돌아온다.
- 예상 단계 수: 약 14 (1.0 → 2.1 → 2.2 → 2.3 → 2.4 → 3.0b 0·1단계 → 3.0b 2단계 카드 → 3.3 → 3.0b 3단계 카드 → 3.4 → 3.0b)
- 관련 목표: 2, 3

## 진행 준비 (진행하는 사람용)
- 휴대폰 또는 노트북 브라우저로 `design/prototype.html` 을 열어요. 노트북이면 창 폭을 휴대폰처럼 좁혀도 돼요.
- 오른쪽 위 '화면 목록' 버튼과, 화면 아래 점선 작은 버튼(예: '기록 있음: 기본', '수입이 일정할 때 보기')은 팀 확인용이에요. 참가자에게 "점선 버튼과 화면 목록은 쓰지 않아요"라고 미리 말해 주세요.
- 기록은 새로 고침하면 사라져요. 과제 2, 3을 시작하기 전에 페이지를 새로 고치고 시작 화면에서 출발해요.
- 진행 1명, 기록 1명이 좋아요. 기록하는 사람은 `ut/sheet.md` 를 복사해 씁니다.
- 전체 시간: 약 25~30분

## 진행 대본

1. **인사**
   "안녕하세요, 시간 내 주셔서 감사해요. 오늘은 재테크를 처음 시작하는 사람을 돕는 '차근차근'이라는 모바일 서비스를 써 보실 거예요. 오늘 평가하는 건 이 서비스이지, 참가자님이 아니에요. 틀린 답은 없어요. 헷갈리거나 막히는 곳이 있다면 그건 서비스를 고쳐야 한다는 뜻이니, 오히려 저희에게 큰 도움이 돼요. 이 서비스는 아직 만드는 중이라 진짜 돈이 오가거나 상품에 가입되지는 않아요."

2. **동의**
   "진행하는 동안 메모를 해도 괜찮을까요? 이름은 적지 않고 번호로만 기록해요. 중간에 그만하고 싶으시면 언제든 말씀해 주세요."

3. **소리 내어 생각하기 설명**
   "화면을 보면서 떠오르는 생각을 소리 내어 말해 주세요. '이게 무슨 뜻이지?', '여기를 누르면 될 것 같은데', '이건 좀 길다' 같은 말이요. 혼잣말하듯이 편하게 하시면 돼요. 그리고 오른쪽 위 '화면 목록' 버튼과 화면 아래 점선으로 된 작은 버튼은 저희 확인용이라 쓰지 않아요."

4. **사전 질문**

   - "금융 상품을 알아볼 때 가장 막히는 건 무엇인가요?"

5. **과제 진행** (과제 하나씩 읽어 주기)
   "이제 상황을 하나 말씀드릴게요. 그 상황이라고 생각하고 서비스를 써 보세요. 다 됐다고 생각되면 '다 했어요'라고 말해 주세요."
   - 과제 1 문장을 읽어 줘요.
   - 과제 2 전에: (페이지를 새로 고침한 뒤) "이번에는 다른 사람이 되어 볼게요. 처음부터 다시 시작해요." 그리고 과제 2 문장을 읽어 줘요.
   - 과제 3 전에: (페이지를 새로 고침한 뒤) "마지막 상황이에요. 이번에도 처음부터 시작해요." 그리고 과제 3 문장을 읽어 줘요.

   - 3분 넘게 같은 곳에서 막히면 "괜찮아요, 이 과제는 여기까지 할게요"라고 말하고 다음 과제로 넘어가요. 기록지에 '실패'와 막힌 화면을 적어요.

## 관찰할 것 (기록하는 사람용)
- 로드맵에 처음 도착했을 때 무엇을 먼저 보는지, '지금 할 일'을 바로 찾는지 (목표 1)
- 기초 용어 미리 보기(2.4)를 펼쳐 보는지, 건너뛰는지. 밑줄 용어를 누르는지 (용어)
- 3.3, 3.4에서 화면을 끝까지 읽는지, 스크롤을 빨리 넘기는지, "길다", "모르겠다", "그만할래요" 같은 말이 나오는지 (목표 2)
- "그래서 어떤 상품을 고르라는 거지?", "은행 이름이 나오면 좋겠다" 같은 말이 나오는지 (목표 3)
