# 자료 지도 만들기

## 시작하며 설명할 것

> 오늘 쓰는 스킬들은 우리 팀 자료를 근거로 일해요. 자료가 여기저기 있으면 클로드가 매번 폴더 전체를 뒤져야 해서 사용량이 많이 들어요. 그래서 먼저 "무엇이 어디 있는지" 지도를 한 장 만들어 둘게요.

## 1. 찾기

- 폴더 목록을 먼저 보세요 (`.git`, `node_modules` 는 빼고). 파일 내용은 이름만으로 알 수 없을 때만 앞부분을 조금 읽으세요.
- 다음을 찾으세요: 서비스 기획서, 퍼소나, 인터뷰나 조사 자료, 메뉴 구조(정보구조, 사이트맵), 와이어프레임이나 화면 HTML, 그 밖의 기획 문서.
- 찾은 기획서에서 서비스 이름, 컨셉 한 문장, 핵심 기능 목록, 주요 사용 시나리오만 뽑으세요. 메뉴 구조에서는 화면 목록만 뽑으세요.

## 2. 화면 ID 맞추기

- 메뉴 구조의 화면마다 ID를 붙이세요. 1뎁스는 1.0, 2.0, 그 아래는 1.1, 1.2, 3뎁스는 1.1.1 처럼요. 이미 ID가 있으면 그대로 쓰세요.
- 와이어프레임 파일이 어느 화면인지 이름으로 짝을 지으세요. 짝이 애매하면 학생에게 물어보세요.
- 메뉴 구조 문서가 없으면, 와이어프레임 파일과 기획서를 보고 화면 목록 초안을 만들고 "초안이에요, 맞나요?" 하고 확인받으세요.

## 3. 저장: docs/project-map.md

```
# 자료 지도

## 서비스
- 이름:
- 컨셉:

## 파일 위치
| 자료 | 파일 |
|---|---|
| 서비스 기획서 | |
| 퍼소나 | |
| 인터뷰, 조사 | |
| 메뉴 구조 | |
| 와이어프레임 | 폴더 또는 파일 목록 |

## 핵심 기능 (기획서 그대로)
1.

## 주요 사용 시나리오 (기획서 그대로)
1. 시나리오 이름: 한 줄 설명

## 화면 목록
| ID | 화면 이름 | 와이어프레임 파일 | 비고 |
|---|---|---|---|

## 비어 있는 것
(기획서에 시나리오가 없다, 메뉴 구조가 없다 등)
```

- 학생 자료의 내용을 고치지 마세요. 지도는 위치와 요약만 담아요.
- 기획서에 주요 사용 시나리오가 없으면 "비어 있는 것"에 적고, 다음 단계(`/flow`)에서 먼저 정한다고 알려주세요.

## 마무리

- 지도를 5줄 이내로 요약해 보여주고, 틀린 곳이 있는지 물어보세요.
- 저장하고 GitHub에 올리라고 알려주세요 (`/save` 가 있으면 `/save`, 없으면 "저장하고 GitHub에 올려줘").
- 다음은 `/flow` 라고 알려주세요.
